# 视觉参考提取与验收

当用户明确提供并认可视觉参考时，本文件是生成 HTML 前和交付前的必读契约。参考只定义表达方式，不转移参考中的领域事实、品牌、正文或无关产品功能。

## 优先级与冲突消解

视觉决策按以下顺序取值：

1. 用户本次明确给出的视觉风格、参考页或截图；
2. 用户已经认可、且与本次内容类型相近的历史视觉基线；
3. `layout-print.css` 的认可基线；
4. 其他通用审美偏好。

上级已经明确时，下级默认限制自动失效。例如参考页可合理采用冷灰画布、白色章节卡、渐变标题区、多种有语义的辅助色、两栏或多栏对照、色带、徽章、荧光重点和悬浮工具；不能因“默认少色、少卡、单列”而弱化它。反过来，只有在颜色、卡片、栏位实际编码优先级、状态、对照或关系时才保留；不可把所有正文装入彩色卡片。

## 制作前：提取可执行规范

完整打开或读取参考页，检查桌面、窄屏和打印（如可用），并在内部形成以下可执行映射后才开始写 CSS。无需将该分析写入成品。

| 维度 | 必须确定的内容 |
|---|---|
| 页面骨架 | 背景、最大内容宽度、外层留白、页头与导航关系、章节在同页中的组织方式 |
| 排印阶梯 | 标题、章节、子标题、正文、辅助文字、表格和控件的字体、字号、字重、行距、间距 |
| 色彩与语义 | 主色、渐变、表面与边框，以及每个辅助色分别表示信息、成功/已确认、注意、风险或对照的哪一侧 |
| 容器与标注 | 章节卡、说明框、表格、对照、流程、知识结构的圆角、边框、阴影、色带、内边距和重点语法 |
| 阅读动作 | 导航位置与选中态、房间切换、进度、搜索、聚焦、悬浮工具以及其显示状态 |
| 响应与打印 | 窄屏的降级顺序、长房间滚动、打印时应隐藏/保留的组件、分页和颜色保真 |

把每一项映射到成品的变量、组件或交互钩子。只复用可观察特征；参考未展示的功能继续依既有能力契约处理。

## 认可的高密度资料视觉基线

没有新参考时，高密度学习、研究和知识资料默认采用以下已认可的语言：冷灰页面底、白色独立章节容器、酒红渐变标题和章节色带、清晰的方形章节编号、低对比度导读、黄色下半部重点高亮，以及有明确含义的蓝/绿/琥珀辅助说明。表格应有可扫读的表头、交替行和首列索引；真实对照可并列，流程和知识结构可图形化；操作从右下角的悬浮组进入。

这是一套起点而不是模板：研究报告可降低工具密度，复习资料可启用搜索和聚焦，风险/警示色只在内容确有相应语义时使用。所有页面保留自包含、可打印和房间交互的要求。

## 交付前：三层验收

### 结构与功能

运行 `validate_html.py`。检查离线资源、能力声明、房间一对一映射、搜索、聚焦、审阅、编辑和打印的声明功能。此项通过只说明结构可用。

### 视觉规范

运行 `validate_visual_contract.py` 并逐项检查：整体色彩与标题区、章节容器、排印阶梯、重点标注、表格和对照、操作区、信息密度。若使用用户参考，应按制作前提取的映射逐项比对；若使用默认基线，按本文件的基线逐项比对。明显退化为低对比度报告页、缺少重点、将语义色压成一种颜色、或把已需要的操作简化为单一按钮，均不通过。

### 真实渲染

在可用浏览器或渲染器中实际检查：

- 桌面：首屏的标题、导航、章节卡和悬浮操作是否形成明确层级；
- 窄屏：房间、表格、对照和工具是否无横向溢出且仍可触达；
- 打印：A4 无截断、孤立标题、意外空白页或不可读重点，屏幕控件隐藏而颜色重点保留；
- 声明交互：逐一完成真实闭环。

有截图条件时，将参考与成品并排核对；无需逐像素一致，但设计语言和阅读优先级必须可观察地一致。当前环境没有可用浏览器或渲染器时，记录哪些项目未验证并继续交付可用文件；不得把静态或关键词检查说成视觉验收通过。
