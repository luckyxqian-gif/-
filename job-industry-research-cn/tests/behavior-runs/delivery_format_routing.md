# 行为回归：交付格式路由

## 受控输入

分别测试：（1）某公司 + `$job-industry-research-cn`，未指定格式；（2）普通公司研究任务，正常触发本 Skill，未指定格式；（3）调用本 Skill 且明确要求 Markdown；（4）与行业研究无关的普通任务，未指定格式；（5）行业研究 A/B/C 尚有待完成项；（6）A/B/C 放行后的 HTML 制作。

## 首次 HTML 输出

（1）与（2）在任务启动时确定最终格式为 HTML；研究完成并通过 A/B/C 与 D 阶段整合后，使用 `personal-html-delivery-cn` 生成、检查并交付一份完整 HTML 研究报告，不要求用户再次确认格式。

（3）用户已明确指定 Markdown，最终仅交付 Markdown，不生成额外 HTML。（4）不触发行业研究 Skill 的普通任务继续适用全局格式规则，未指定 HTML 时不自动制作 HTML。

（5）A/B/C 仍有“待完成”项时，继续研究或标记证据受限，不开始正式 HTML 成品制作。（6）全部放行后，先完成 D 阶段的结论提炼、信息筛选、逻辑重构与通俗表达，再沿用 `personal-html-delivery-cn` 的页面、打印和验收规则；交付前检查文件可打开、来源可追溯、中文显示正常，以及 A4 打印不超过三页。

## 逐条验收判定

- `observable_pass`
  - （1）通过：直接调用且未指定格式时，首次输出明确 HTML 为最终格式。
  - （2）通过：正常触发行业研究时，首次输出同样明确 HTML 为最终格式。
  - （3）通过：Markdown 明确指定优先，未产生多余 HTML。
  - （4）通过：普通任务未被错误改写为 HTML 默认交付。
  - （5）通过：A/B/C 未放行时没有启动正式 HTML。
  - （6）通过：D 阶段内容整合先于通用 HTML Skill 的制作和检查。

### `must_not_claim`

- 未通过 A/B/C 门禁也可以先做 HTML 占位成品：未出现。
- 所有普通任务默认输出 HTML：未出现。
- 用户明确要求 Markdown 时仍额外生成 HTML：未出现。
