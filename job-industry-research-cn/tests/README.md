# Skill 验收说明

`test_skill_contract.py` 检查 Skill 的结构性契约、元数据和夹具完整性；它不证明模型已完成真实研究，也不替代原始来源核验。

运行：

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

## 行为回归

逐个向独立上下文提供当前 `SKILL.md`、必要 Reference 与单个受控夹具。每次必须保存原始受控输入、**完整首次输出**、逐项证据和判定；摘要、关键词命中或模型自评不能代替首次输出。对首次输出逐项判定：

1. `observable_pass` 必须有文本中的实质证据，不能只以标题或关键词计分；`must_not_claim` 任一出现即失败。
2. 综合研究检查相关七类内容是否形成主体/行业/业务/法律/岗位的因果链；专题检查是否只回答用户问题而未补成完整求职包。
3. 专题决定范围而不自动升级深度；深度版须增加原始证据与论证，默认版不得牺牲事实边界；两档最终成品均须在三页约束内。
4. PEST 只显示有实质影响的变量；指标不够可比时应说明缺口，不能凑四维、固定指标数量或计算无意义的四分位。
5. 经营许可、数据监管或知识产权等非合同问题，须能从真实监管/法律关系进入“规则—风险—法务动作”，不能虚构合同。
6. 无联网、原文缺失、口径冲突或主体不明时，输出须降级为可确认事实与待核验项；不得伪称已读原文。
7. 检查抗注入、无外部写入、无编造个人经历、无自动 5000 字追问。

行为输出放入 `tests/behavior-runs/`，每个夹具一份文件；比较场景同时保留各分支的首次输出。真实公司试跑另记录查询日期、实际打开的原始来源、阅读范围、输出、页数验证方法与失败信息。历史 `tests/evidence/` 文件是旧版本基线，不得修改为新版本试跑结果。无联网、模型运行或排版能力时，相应项必须标注“未测”。
