# 通用 HTML 交付

## 边界

本 Skill 只负责把已经形成的内容组织成结构完整、重点清楚、可以按需深入的 HTML 交付件。领域事实、分析方法和业务流程由调用方持有；不改变未经授权的领域结论，也不嵌入具体领域、项目或任务类型的规则与示例。

当用户要求的是既有材料的“形式优化”时，保留正文事实、判断与覆盖范围；先另存副本，再在副本中重组层级、重点与交互。除非用户明确授权，不覆盖已发布版本，也不为了版式删减用户交付的正文。默认只交付用户指定的版本；只有用户明确要求保留多版本时，才提供入口与切换。

用户指定其他文件格式时遵从用户选择。只有用户明确要求 HTML，或上游 Skill 已明确把最终交付路由到本 Skill 时，才生成 HTML。用户已将最终 HTML 的中国内地公开发布设为默认交付要求：本 Skill 的本地质量门禁通过后，必须交给 `personal-html-publish-cn` 取得经核验的 HTTPS URL。用户明确要求不发布时，保留本地 HTML 并在交付中注明该例外。

## 执行

1. **读取交付约束。** 明确本次目的、读者已有知识、使用场景、方向与尺寸、篇幅上限、必须保留内容，以及是否需要打印、审阅标记、板块切换或直接编辑正文。把“本次交付时间”和内容自身的资料截至时间分开；导航之前需要什么内容，由本次交付的知识密度决定，不预设页头、导读、总判断或工具栏。
2. **先搭完整体系。** 在选择卡片、表格或关系图之前，先建立能解释全貌的逻辑框架。完整读取并执行 [信息体系与表达](references/information-hierarchy.md)。
3. **在每个真实板块内安排主次。** 每个板块先呈现完成目标不可缺少的结论，再讲清读者理解该结论所需的关系、机制或背景，最后才放可展开的精确数据与补充材料。知识总结、复习资料或学习说明还要主动选出真正需要被快速调出的知识点，并以可见的系统重点实际呈现；具体取舍规则见 [信息体系与表达](references/information-hierarchy.md)。系统重点不是等待读者自己标记的空壳；启用 `focus` 或 `review` 时，聚焦功能必须能立即聚焦这些预先呈现的重点。这是内部编辑判断，成品不得出现“必须知道”“需要理解”“按需查看”等过程标签，也不得另写阅读取舍说明。
4. **先确定视觉基线，再选择表达。** 完整读取并执行 [视觉、交互与打印契约](references/visual-print-contract.md)。只要用户提供并认可视觉参考，先完整检查参考页并按 [视觉参考提取与验收](references/visual-reference-workflow.md) 形成内部视觉规范；其中的整体设计语言、层级、密度、标注和操作区要实际约束成品。优先级固定为：**本次明确风格与参考 ＞ 用户已认可的历史视觉基线 ＞ 本 Skill 默认基线**。高优先级参考一旦明确，低优先级默认限制自动让位。不得复制参考的正文、品牌或无关功能。用户已明确采用独立内容房间时，房间模型仍是既定结构；只吸收参考的视觉与交互语言，不以参考的整页滚动替换房间。组件服务真实信息功能，不反过来切碎内容。

   **有参考时，风格相同是验收目标，不是灵感来源。** 先从参考建立一份仅供内部使用的“视觉签名”，至少逐项记录：画布与内容最大宽度、页头/导航/内容容器的关系、字号与行高阶梯、间距节奏、圆角/边框/阴影、色彩及其语义、重点标记语法、表格与说明框的形态、响应式断点，以及阅读操作区的布局和状态。每项都必须映射到成品的 CSS 变量、选择器或交互钩子；参考中未出现的内容组件，必须沿用这套签名的现有模式，而不是回退到默认组件样式。

   有参考时优先复用其 CSS 架构和可观察的规则，再替换内容与必要的语义类；不要先生成默认页面，再用若干“视觉增强层”、重复选择器或样式覆盖去接近参考。成品每个选择器只保留一个最终权威来源；清除被替代的规则，而非在文件末尾继续叠加。除非内容结构或响应式阅读确有必要，不得任意改变参考的内容宽度、正文基准字号、标题阶梯、关键间距、容器形状、导航位置或重点标注方式。功能新增可以改变信息结构，但其控件、状态和间距必须继承参考的设计语言。
5. **按内容生成自包含文件。** 不套固定页面模板，不规定栏目数、组件数或板块名称。没有明确视觉参考时，按本次视觉规范从 [布局与打印能力片段](assets/layout-print.css) 选择并内联样式；它提供认可的高密度资料视觉基线，但可依内容调整。有明确参考时，`layout-print.css` 只可补足参考未定义且本次确有需要的能力，不能覆盖视觉签名。交互必须以 [交互能力片段](assets/interactions.js) 为基线实现，不另写看似相近但未验证的简化控制器。最终 HTML 不依赖外部字体、脚本、样式、图片或服务器；核心正文在 JavaScript 不可用时仍可阅读。
6. **按需组合交互。** 先数清可以独立阅读的真实主题：少于 3 个时由内容决定是否使用导航；达到 3 个及以上时，必须声明 `navigation`，在页首设置导航，并把每个入口映射到唯一的内容房间。侧边锚点、整页滚动目录或多个入口共用一个房间都不满足这一要求。`search` 用于长篇、需要反复检索的资料；`focus` 只提供预置重点的聚焦／显示全部；`review` 在 `focus` 基础上再提供红色划线、移除标记和保存修改副本；`editor` 用于本地正文编辑；`print` 用于打印优化。不要为了一个聚焦按钮声明 `review`，也不要为未接入的能力放置控件。控件用动作与对象命名；导航与阅读操作分开，后者置于可触达的悬浮操作区。需要编辑大部分连续正文时，把 `data-editable` 标在该正文容器或少量自然板块上，不逐段、不逐句标记。一个交付件只保留一套生效的交互控制器，避免旧脚本或替代实现与内联资产竞争。能力可以组合，静态阅读页可以不启用任何一项。详情见 [视觉、房间交互与打印契约](references/visual-print-contract.md)。
7. **三层验证后完成本地交付。** 先运行 `scripts/validate_html.py <成品.html>` 完成结构与功能检查；再运行 `scripts/validate_visual_contract.py <成品.html> --profile <reference|baseline|custom>`，它只检查可静态验证的视觉契约，不能代替视觉判断；最后按 [视觉参考提取与验收](references/visual-reference-workflow.md) 在当前环境允许的真实浏览器或渲染器中检查桌面、窄屏和打印。对每一项声明的交互执行一次闭环：搜索能够定位与切换结果；聚焦后未处理正文退为浅灰而系统重点仍清晰；`review` 还要验证标记选中文字后出现红色下划线且刷新保留、保存副本包含修改；`editor` 还要验证可输入、浮动工具栏可用、退出后刷新保留。视觉语言明显偏离参考、章节层级不清、重点标注缺失或交互区被简化，均视为未通过。不能在当前环境完成真实渲染检查时，明确列出未验证项目；不得把静态校验通过称为完整视觉验收。页数只能通过目的导向的内容取舍满足，不得缩小正文或删去必要解释。
8. **发布后完成公开交付。** 对最终单文件 HTML 调用 `personal-html-publish-cn`。将发布器返回的精确 HTTPS URL、版本、文件指纹和状态写入交付说明；只有状态为 `published` 且 URL 已核验时才称为“公开发布完成”。`configuration_missing`、`confirmation_required`、认证/权限失败、上传失败或 `verification_failed` 均只能报告“本地交付完成，公开发布未完成”，并如实列出状态和下一步，不得把本地文件或控制台地址冒充公开链接。

## 完成门禁

- 本地交付完成时，交付一个真实、可打开、可带走的 `.html` 文件，而不是代码片段或 Markdown 预览。
- 除非用户明确要求不发布，公开发布完成还必须包含 `personal-html-publish-cn` 返回并核验过的精确 HTTPS URL；未获得 `published` 状态不得称为完整交付。
- 用户提供并认可视觉参考时，成品已落实其可观察的整体视觉语言；若没有新参考，则采用本 Skill 的认可视觉基线，而非随机另起一套样式。
- 用户提供并认可视觉参考时，成品已落实其完整的可观察视觉签名，而非只沿用配色、标题或局部组件。
- 有参考时，成品使用一套整合后的最终样式规则；不得保留“通用初稿 + 视觉增强层”的叠加式 CSS，也不得让默认基线覆盖参考已定义的属性。
- 内容先形成完整体系，再使用局部组件；读者能看见各部分的因果、层级、对照、演进或应用关系。
- 每个真实板块内部都有清楚的“关键结论—必要解释—补充细节”主次，但这些内部层级不作为可见栏目名称或过程说明。
- 页面显示本次交付时间；存在独立资料时点时另行标明。
- 导航之前可以出现任何本次目标真正需要的内容，也可以不设独立区域；其结构、数量、顺序和形式全部由本次内容关系决定。本 Skill 不预设页头清单，也不把示例中的元素视为必选项。
- 启用 `focus` 或 `review` 时，至少有一个真实正文节点承载系统重点；聚焦不隐藏正文、不改变板块结构或事实，但应把未标注的解释、例子、表格正文与题目背景降到接近背景的浅灰，让读者首先只看见经过特殊处理的重点；刷新后恢复上次状态。启用 `review` 时，用户红色下划线还必须可取消、持久化、打印并保存进修改副本。
- 启用 `editor` 时，使用最少数量、覆盖完整阅读单元的 `data-editable` 容器；选区格式工具栏、撤销／重做、本地持久化和导出修改副本真实可用；页面不依赖 AI 或远程编辑服务。
- 任何显示给用户的标记、编辑、导出或聚焦控件都必须在真实浏览器中完成对应动作；不能把尚未接入的动作当作按钮交付。
- `search` 启用时，搜索面板、命中数量、上一条／下一条与结果定位真实可用；搜索、聚焦、打印和回顶等阅读操作不混入房间导航。
- 独立主题达到 3 个及以上时，启用 `navigation`：页首导航中的每个入口都只对应一个真实内容房间，每个房间也只被一个入口指向；房间可独立纵向阅读，不通过整页滚动把用户送回页首；关闭 JavaScript 时全部正文仍可连续阅读。
- 启用 `print` 时，真实打印无横向溢出、孤立标题、截断组件或意外空白页；调用方声明页数上限时实际打印不超限。
- 参考文献只列实际来源及其支持内容，不出现 Agent 的推理、检索日志、证据矩阵、设计理由或调试记录。
- 交付说明只报告文件、用户可见能力、验证结果和仍会影响使用的限制。
