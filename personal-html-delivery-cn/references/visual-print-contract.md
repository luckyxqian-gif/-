# 视觉、房间交互与打印契约

## 视觉决策

成品应像已经完成取舍、可直接使用的资料，而不是后台、卡片拼盘或格式模板。版式由内容关系决定：结论有足够面积和停顿，解释紧随结论，证据和精确材料退到低干扰层。

视觉优先级以 [视觉参考提取与验收](visual-reference-workflow.md) 为准：用户本次明确风格与参考最高，其次是已认可历史基线，最后才是本文件的默认基线。默认从不覆盖明确参考，也不要求用户逐项解除默认限制。

### 默认视觉基线

未提供新参考时，使用 `assets/layout-print.css` 的高密度资料基线：冷灰画布、白色章节卡、酒红渐变标题区与章节色带、清楚的无衬线排印阶梯、黄色局部重点高亮、右下角悬浮阅读操作。它适用于学习、研究、知识整理等需要扫读和复用的资料；每次仍按内容调整密度与组件。

- 正文中性色负责正常阅读；酒红负责章节身份、主要动作和核心结论；蓝、绿、琥珀和灰仅在分别表示信息/对照、已确认、注意/易错、补充/弱化时使用。颜色必须有信息含义，不能按内容类别轮换装饰。
- 使用位置、字号、字重、留白、边框和版面面积表达主次；颜色不代替层级。标题、正文、导航和控件保持同一系统无衬线字体族，除非参考或品牌明确要求其他字体。
- 独立章节可用白色卡、顶部色带和方形编号。表格可采用浅色表头、交替行、首列索引和悬停态；真实对照、流程、知识结构可横向展开为两栏或多栏，但栏位必须对应真实关系。连续论证应保留为正文，不能为了好看切成卡墙。
- 系统重点可从粗体、文字色、淡色底、划线、色条和结论框中选择一种或复合两种，落在可复述的最小词句、数字、例外或判断上。默认基线以黄色下半部高亮为快速定位语言。用户红色下划线与系统重点语义分开。
- 说明框、优先级标签、场景条、对照和警示都必须有实际信息职责；不让每个组件同等醒目，也不把普通文字伪装成警告。

### 参考优先时的实现

用户提供可访问的参考页、截图或已认可作品时，完整检查实际字体、尺寸、行距、背景、容器、色彩语义、重点语言、导航和操作区，再将结果映射到本次 CSS。不得只取一两个色值而让整体版式退回默认报告风格。

可以因内容改变参考的栏目数、信息组件或工具数量；不得移除参考中承担阅读任务的可观察特征。参考页面若使用冷灰背景、白色章节卡、渐变头部、语义色、编号徽章、高亮、表格/对照/流程和悬浮工具，应按本次内容保留其对应的功能性表达。参考的领域内容、品牌、无关按钮或冲突的房间模型不得复制。

## 信息功能与组件

- 可直接背诵的规则或结论：`annotation-box` 或语义说明框；需要快速调出的最小词句另标为 `system-key`。
- 易混边界、题目回忆或例外：`evidence-qa`，先问题/错因，后结论。
- 两个或多个概念、条件或版本的真实比较：`comparison`；窄屏按逻辑顺序改为纵向。
- 有步骤、情境或应用映射：`context-scene`、流程或知识结构；不用等权小卡代替连续关系。
- 复习范围或本节检查项：`summary-strip`，仅在有真实范围信息时出现。
- 纯解释、证据、出处和普通表格：保留正文或表格身份，不因“好看”变成重点框。

同一视口只保留一个视觉主角。组件不是模板清单；没有真实信息功能就不添加。

思维导图只在能比连续文本更快表达关系时使用：桌面端以中心主题在左、一级分支向右、二级内容随分支展开为优先形态；窄屏改为清楚的纵向分组，不要求横向拖动。

## 能力声明

在 `<html>` 的 `data-capabilities` 中只声明实际启用的能力。交互型页面同时提供 `data-document-key` 与 `data-content-version`；内容实质更新时递增版本，导出副本生成新的文档键。

- `navigation`：独立主题达到 3 个及以上时必须使用；每个入口对应一个唯一内容房间。
- `search`：长篇、需要反复定位术语、规则或资料时使用；需提供搜索入口、输入、命中状态、上/下一条和关闭。
- `focus`：在预置系统重点与完整正文之间切换；不要求用户选区标记。
- `review`：在 `focus` 上增加标记选中文字、移除标记与保存修改副本。
- `editor`：用户明确要求本地直接修改正文时使用；每个自然编辑单元标记为 `data-editable`。
- `print`：用户要求 A4 打印优化时使用。

导航只承担内容房间切换。搜索、聚焦、打印、编辑、保存和回顶等阅读操作位于右下角悬浮操作区；控件用“动作 + 对象”命名。一个页面只保留一套由 `assets/interactions.js` 提供的有效控制器。

## 内容房间

导航不是目录锚点，也不是把读者滚回页面顶部。独立主题达到 3 个及以上时，页首导航中的每项对应一个**独立内容房间**；点击后仅切换导航下方的房间，进入房间后在该房间内纵向阅读。

- 使用 `.room-stack` 包裹房间，每个房间使用 `data-section` 与 `data-room-scroll`；`--room-height` 由实际页头与导航高度校准。房间内部纵向滚动，不借整页滚动返回前一个主题。
- 当前房间有明确选中态；哈希、刷新、浏览器后退和前进恢复同一房间。
- JavaScript 关闭时所有房间按内容顺序连续显示；打印时同样连续输出，导航和屏幕工具不打印。
- 内容很短、只有一个自然主题或切换会破坏阅读逻辑时，不创建导航和房间。

## 聚焦、审阅与编辑

启用 `focus` 时，提供“聚焦重点／显示全部”。聚焦是信息级复习状态：未作特殊处理的解释、例子、表格正文与题目背景退为浅灰，`system-key`、用户标记、完整结论和真实优先级标签保持清楚；不能让带一个重点的大容器整体恢复深色。

每个真实知识板块至少有一个可聚焦的最小信息单元。`review` 还必须支持同段连续选区的红色下划线、点击移除、刷新恢复和保存修改副本。所有交互是阅读辅助，关键结论和必要解释不依赖 JavaScript。

用户明确要求编辑时，提供本地编辑模式、选区附近的浮动格式工具栏、撤销/重做和退出编辑。使用最少数量、覆盖完整阅读单元的 `data-editable` 容器；修改与用户高亮保存在浏览器本地，导出副本包含当前文字、格式和高亮。编辑完全本地运行，不显示“AI 编辑”，链接只接受 `https:`、`http:`、`mailto:` 或页内锚点。

普通阅读型成品不机械加载编辑器；只有用户明确需要直接编辑正文时才声明 `editor`。

## 排印、响应与打印

- 屏幕正文以 `15px / 1.72` 为可调整起点；参考页面优先于默认数值。字号、行距和留白只能围绕阅读密度调整，不能靠缩小正文或压行距换页数。
- 窄屏时，导航和悬浮操作保持可触达；对照、卡片组、流程和表格按其真实阅读顺序改为单列或可控横向表格，不能出现正文横向溢出。
- 打印使用 A4，正文五号 `10.5pt / 1.45` 为基线；调用方可以声明最高页数。隐藏导航、搜索、悬浮工具和编辑边界，保留用户标记、系统重点和语义色；避免横向溢出、孤立标题、截断组件和意外空白页。

## 交付检查

交付必须通过三层检查：结构与功能、视觉规范、真实渲染。静态检查只验证可声明的钩子与离线性；视觉检查按提取到的参考/基线逐项核对；真实浏览器或渲染器检查桌面、窄屏、打印和声明交互的闭环。

本地三层检查通过后，最终单文件 HTML 还要由 `personal-html-publish-cn` 发布为中国内地可访问的精确 HTTPS 版本 URL。发布不改变本契约中的内容、视觉或交互规则；发布器的预检、版本路径、权限边界和远端核验独立执行。除非用户明确禁止发布，未取得发布器的 `published` 状态时，只能报告本地交付完成。

`focus` 至少验证系统重点聚焦后的清晰度与普通正文退场；`search` 至少验证关键词定位、命中切换和关闭；`review` 至少验证标记写入与刷新恢复；`editor` 至少验证输入、选区格式、退出和刷新恢复。未能在当前环境进行真实渲染的项目必须如实列出，不能以“文件已生成”或静态校验通过代替完整视觉验收。
